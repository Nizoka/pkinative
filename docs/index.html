Why pkinative

A reader for hostile bytes, complete on the profile it claims and explicit about the profile it does not.

Strict by default

DER admits one encoding per value, and every X.690 §10–11 violation throws. Two encodings of one value is how a signature covers bytes two parsers read differently. BER is an explicit opt-in.

Zero dependencies

Nothing to audit but this. No node: import, no process, no filesystem, no network — checked on the shipped bundle, not just the source.

Safe on hostile input

Every loop over untrusted bytes consults a named, CWE-tagged limit. The decoder is iterative, so nesting depth ends in a typed error and never in a stack overflow.

Complete on RFC 5280

Every field and all eighteen standard extensions, decoded and typed — not a subset with the awkward ones left as raw bytes.

Honest about profiles

A structural violation throws; a profile deviation real issuers commit becomes a diagnostic carrying its RFC clause. Never both, and never silence.

No cryptography it should not own

No signing, no key generation, no arithmetic on secret material in TypeScript. Hashing covers public data; verification goes through Web Crypto from 0.3.

One build, every runtime

The same bundle on Node, browsers, Deno, Bun and Workers. Tree-shakeable: the 300-name OID registry never enters a certificate parser's bundle.

Built for agents

Stable machine-readable error codes, a diagnostics channel, llms.txt, a generated API manifest — and gate rules that prove an agent can use every export from the docs alone.

Three calls

Every example below is an executable recipe, run and asserted on every test run.

import { decodePem, formatDistinguishedName, getExtension, parseCertificate } from 'pkinative';

for (const { bytes } of decodePem(pemText, { label: 'CERTIFICATE' })) {
    const cert = parseCertificate(bytes);
    console.log(formatDistinguishedName(cert.subject));
    console.log(new Date(cert.validity.notAfter.epochMilliseconds).toISOString());
    console.log(getExtension(cert, 'subjectAltName')?.names.length ?? 0);
}
import { decodeExtensionValue, getExtension, parseCertificate } from 'pkinative';

// Eighteen standard extensions, each typed by its `kind`.
const cert = parseCertificate(der);
getExtension(cert, 'basicConstraints')?.cA;
getExtension(cert, 'keyUsage')?.usages;
getExtension(cert, 'nameConstraints')?.permittedSubtrees;

// Or keep them encoded, and decode only what you need.
const lazy = parseCertificate(der, { decodeExtensions: false });
decodeExtensionValue(lazy.extensions[0].oid, lazy.extensions[0].valueDer);
import { parseCertificate, PkiError, PkiLimitError } from 'pkinative';

try {
    // A caller that expects small certificates can say so; every other
    // limit keeps its default.
    parseCertificate(untrusted, { limits: { maxExtensions: 4 } });
} catch (error) {
    if (error instanceof PkiLimitError) console.error(error.code, error.limit);
    else if (error instanceof PkiError) console.error(error.code);
    else throw error;  // a TypeError escaping the parser would be a bug
}

Every export named here is in api.json; the runnable sources are in llms-recipes.txt.

For AI agents

Every failure is a typed error with a stable code you can branch on. Every export, its module, signature and thrown errors are in a generated manifest. Seven gate rules prove an agent can name and use every export from the published documentation alone — not as a claim, as a check that fails.

Agent brief

Origin

pkinative is the third library of the native family, after pdfnative and zipnative. It began as pdfnative's PAdES signature stack, where an ASN.1 decoder that guessed was a liability, and became the library that reads the certificate rather than the one that trusts it.

The same doctrine runs through all three: zero runtime dependencies, one quality gate, conformance against corpora the project did not write, and human review before anything is published.
