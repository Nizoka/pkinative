# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). Versions below 1.0.0 are git tags and are not published to npm.

## [Unreleased]

### Added

- **docs: the site previews locally, and its social cards render** — `npm run docs:serve` serves `docs/` the way a static host does. It exposed a defect it was the only way to see: under `cleanUrls` the link `guides/index.html` took two redirects and landed on a URL whose base directory is the site root, so the guides index loaded without its stylesheet. The index is now linked and canonicalised as `guides/`, held there by the new `clean-url-safe` rule. `og:image` and `twitter:image` pointed at an SVG, which no social platform renders, so every share card was blank: both images are now committed PNGs with declared dimensions, plus a 1280×640 `social-preview.png` for GitHub. `declared.socialImages` records the SHA-256 of each SVG source, so a raster cannot silently go stale.
- **docs: the library is provably usable from its documentation alone** — five new verify-docs rules and two suite assertions replace the question with a measurement. `export-named` requires every export a caller must write — derived, not hand-listed: every function, class and constant, plus every type occurring in an exported signature. `member-tsdoc` requires a summary on all 283 interface members of `api.json`, which is the only place the 57 result-only shapes are ever described. `extension-kinds-complete` requires all twenty extension kinds in both the quick start and the agent brief, and refuses one that does not exist. `option-fields-named` covers every option field, `surfaces-parity` holds `docs/data/surfaces.json` to the package in both directions. The recipes suite now asserts that every runtime export appears in a recipe that runs, and that the code blocks of the README and the agent brief are the marked regions of those recipes byte for byte.
- **docs: two recipes and the last unnamed exports** — `recipes/asn1-primitives.ts` covers the BOOLEAN, NULL, BIT STRING and OCTET STRING pairs, `encodeTlv`, `decodeAsn1Sequence` and the SET/SET OF distinction; `recipes/agent-brief.ts` makes the brief's sample executable. With `OID_REGISTRY`, `DEFAULT_PKI_LIMITS` and `PkiCertificateError` added to the recipes that already touched them, all 43 runtime exports are demonstrated by code that runs.

### Changed

- **docs: the agent brief names all twenty extension kinds** — it named nine, so the other eleven were undiscoverable and the list read as open-ended. Its code sample is now a function that runs, rather than a top-level loop over an undefined variable.
- **test: workflow invariants** — `tests/tools/workflows.test.ts` normalises CRLF on the way in, without which every multi-line assertion in it mismatched silently on a CRLF working copy. Two new invariants: the exact set of workflow files, and one SHA per action across the tree.
- **test: `count-tokens` holds only the top changelog entry to current counts** — an entry for a released version records what that version shipped, and forcing today's numbers into it would falsify the record.

## [0.1.0] – 2026-09-19

### Added

- **build: attested release tarball and install smoke test** — `release-assets.yml` builds every pre-1.0 release from its tag, runs the full publish gate with the conformance corpora, packs the tarball, proves it installs and loads as ESM and CJS, and attaches it with a CycloneDX SBOM and Sigstore build provenance: a git install cannot work, because `dist/` is not committed. `npm run smoke:install` (a CI gate step) installs the packed tarball into an empty project and loads every runtime export both ways. `publish.yml` now fetches the corpora its publish gate needs. The architecture test refuses any Web Crypto key operation in `src/`, and `formatDistinguishedName` also escapes C1 and bidirectional control characters.
- **docs: README, guides, agent files and the pkinative.dev landing page** — a complete README (why, how it compares on registry facts, installation from the git tag, quick start, security model, conformance, known limitations, what pkinative will not do); five guides — quick start, security model, conformance, errors and diagnostics, choosing a library — rendered by `npm run docs:guides` into static pages with no JavaScript and no third-party load; `llms.txt`, `llms-full.txt`, `llms-recipes.txt`, `llms-index.json` and an agent brief; `docs/data/surfaces.json` and a dated comparison file; six executable recipes (`recipes/`), the README quick start among them, run and asserted on every test run; and a landing page with SEO, Open Graph and JSON-LD metadata. verify-docs gains fourteen rules: generated pages and LLM files stay in sync, links and anchors resolve, every page carries its metadata and appears in the sitemap, the JSON-LD version and the verified-on date match `ecosystem.json`, the palette meets WCAG 2.2 AA contrast, the docs import only real exports and quote only real counts, and release notes carry their mandatory sections.
- **build: tree-shaking probes, API manifest and benchmarks** — `npm run verify:bundle` (a CI gate step) bundles single imports from `dist/` with esbuild and holds each to a byte budget (measured + 15 %) and to forbidden markers: `decodeAsn1` ships no OID registry, hash or PEM code; `decodePem` no ASN.1 decoder; `parseCertificate` no OID name registry and no SHA; `getOidName` no decoder. `docs/assets/api.json` (`npm run docs:api`) lists the 127 public exports with module, signature, summary, the error classes each function throws, its @param and @returns text, and — for every interface — its members with their types, inherited ones included, so an agent never has to guess a field name; the verify-docs rules `api-json-sync` and `tsdoc-complete` (summary, every `@param`, `@returns`, `@throws`) keep it honest. `npm run bench` measures the hot paths on the public fixtures; `bench/RESULTS.md` records the numbers with their run context.
- **test(conformance): the independent conformance gate** — `scripts/validate-certs.ts` runs the built package over x509-limbo and Project Wycheproof, pinned by commit and SHA-256 (`scripts/lib/corpora.ts`, `.github/checksums/`, downloaded by `npm run conformance:fetch`). All 30 361 unique x509-limbo certificates parse or are refused only where every limbo case using them expects failure, with every refusal held to a reviewed baseline (`scripts/data/limbo-refusals.json`, 564 entries); all re-encode byte for byte, their TBS and signature boundaries agree with a walker that never imports `src/`, and every parsed one agrees with `node:crypto` (OpenSSL 3.0) and a sample with the openssl CLI (3.5) on serial, validity, CA flag and fingerprint. All 1 530 Wycheproof ECDSA signatures on P-256, P-384 and P-521 decode strictly: every valid one parses, every encoding defect is refused. `conformance.yml` runs it on every change as a required check, the gate's publish profile runs it, and the verify-docs rule `corpus-pin-parity` keeps the pins, checksums, notices and canaries in step. Six public certificates (ISRG Root X1 and X2, Let's Encrypt E7 and R12, the letsencrypt.org leaf, the RFC 8410 §10.2 example) are known-answer fixtures with their provenance and SHA-256 in `tests/fixtures/PROVENANCE.md`.
- **feat(x509): every standard extension** — `parseCertificate` now decodes basicConstraints, keyUsage (nine named bits), extKeyUsage, subjectAltName, issuerAltName, subjectKeyIdentifier, authorityKeyIdentifier (all three fields), nameConstraints (subtrees with masks and bounds), certificatePolicies (CPS and user notice qualifiers), policyMappings, policyConstraints, inhibitAnyPolicy, authorityInfoAccess, subjectInfoAccess, cRLDistributionPoints, freshestCRL, the Certificate Transparency SCT list (kept TLS-encoded) and id-pkix-ocsp-nocheck. Each value is decoded in place, so offsets stay absolute; a value that does not match its definition throws `PKI_X509_EXTENSION_MALFORMED`, and `decodeExtensions: false` keeps every extension raw for tools that must read what they cannot decode. An unrecognised extension is kept as `unknown`, with a diagnostic when it is critical. A DEFAULT value encoded explicitly (version v1, critical FALSE, cA FALSE, a subtree minimum of 0) is read as encoded with the `PKI_DIAG_DEFAULT_ENCODED` diagnostic, as Go, OpenSSL and BoringSSL read it — the RFC 8410 §10.2 example certificate carries three; `strict: true` refuses it. New diagnostics also fire for pathLenConstraint without cA, an empty keyUsage, trailing zero bits in a named bit list, non-critical nameConstraints, an unpaired authorityCertIssuer/serial, a duplicated policy, an empty policyConstraints and an empty alternative name. `getExtension(cert, kind)` returns one typed extension; `decodeExtensionValue(oid, der)` decodes one on its own. The parser is held to `node:crypto.X509Certificate` on serial, names, validity, SAN, CA flag, extended key usage and fingerprints.
- **feat(x509): certificate envelope, algorithms, names, general names and public keys** — `parseCertificate` reads every RFC 5280 §4.1 field: version, serial number (bytes, hex and bigint), both signature algorithms, issuer and subject, validity, the subject public key, the unique identifiers in their order, and the extensions kept as encoded, each OID at most once, with `maxExtensions`. Profile concerns real issuers commit are diagnostics recorded on `certificate.diagnostics`: an oversized or non-positive serial, a signature algorithm mismatch, RSA parameters other than NULL, a GeneralizedTime before 2050 or with a fraction, an inverted validity, an empty issuer, an empty subject without a critical subjectAltName, unique identifiers in v1, extensions before v3 and an RDN out of DER SET OF order. Public keys are checked against their definitions: RSA and RSASSA-PSS (a positive modulus and exponent), EC (named curve and point length on P-256, P-384 and P-521), Ed25519, Ed448, X25519, X448 and ML-DSA-44/65/87 (parameters absent, exact key length); any other algorithm is kept as `unknown`. `formatDistinguishedName` writes RFC 4514 strings and escapes control characters. The GeneralName reader decodes all nine forms, IPv6 in RFC 5952 text and name-constraint masks; the extensions that use it arrive with the extension decoders. Parsing never verifies a signature.
- **feat(oid): name registry** — `getOidName` and the frozen `OID_REGISTRY` (each entry an `OidRegistryEntry`: OID, name and defining standard) cover name attributes, certificate and CRL extensions, extended key usages, CA/Browser Forum and ETSI policies, qualified-certificate statements, CMS and CAdES attributes, PKCS #12 and password-based encryption, and the RSA, ECDSA, EdDSA, ML-DSA, SLH-DSA, ML-KEM, SHA-2, SHA-3 and AES algorithm identifiers. Every OID and every name appears once, and every OID round-trips through the codec. Lookups go through a `Map`, so an input such as `__proto__` never resolves. The registry is data that only `getOidName` pulls in; the certificate parser never imports it.
- **feat(hash): certificate fingerprints** — `computeFingerprint` (SHA-1, SHA-256, SHA-384, SHA-512, synchronous), `computeFingerprintAsync` (Web Crypto when the host has it, the same bytes otherwise) and `formatFingerprint`. The digests cover public data only and are not exported as general-purpose hashes. One FIPS 180-4 padding routine serves all four: pdfnative's SHA-256, the source of the compression function, omitted the high word of the bit length and hashed every input of 2^29 octets or more wrongly. The SHA-384/512 compression loop allocates nothing. Held to `node:crypto` on every length from 0 to 300 octets, one million octets and 2 000 random inputs.
- **feat(pem): RFC 7468 decoding and encoding** — `decodePem` reads every block of a text in `strict` mode (exact boundary lines, 64-character base64 lines, no headers) or `lax` mode (whitespace, any line length, RFC 1421 headers, each deviation reported once); both modes ignore explanatory text around blocks, and refuse labels outside the grammar, mismatched END labels, unterminated blocks and non-canonical base64. An optional `label` refuses any other block, so a private key is never read as a certificate. `encodePem` writes the strict form. The PEM layer never imports the ASN.1 layer.
- **feat(asn1): strict X.690 decoder, value readers, OID codec and DER encoders** — `decodeAsn1` and `decodeAsn1Sequence` decode iteratively (nesting is the `maxDepth` limit, never the call stack), strict DER by default and BER with `encodingRules: 'ber'`; every node is frozen and keeps zero-copy views of its exact bytes. Under DER, indefinite and non-minimal lengths, non-minimal or overflowing high tags, constructed strings, wrong primitive/constructed forms, stray end-of-contents markers and trailing bytes are refused with a stable code; under BER each tolerated construct is reported once. Readers for BOOLEAN, INTEGER (bigint and safe number), NULL, BIT STRING, OCTET STRING (BER segments joined under `maxBerSegments`), eight character string types and both time types (impossible dates refused, never rolled over; years 0000–9999 exact). `encodeOid`, `decodeOid`, `isValidOid` and `readObjectIdentifier` with exact arcs of any size. DER encoders that refuse what DER cannot represent, `encodeSetOf` with X.690 §11.6 ordering, and `encodeAsn1Node`, which re-encodes a DER-decoded tree byte for byte. A length encoded as `84 80 00 00 01` — negative under pdfnative's signed shift — is a `PKI_ASN1_TRUNCATED` or `PKI_ASN1_LENGTH_OVERFLOW` here.
- **feat(core): errors, limits and diagnostics** — the `PkiError` family (`PkiEncodingError`, `PkiCertificateError`, `PkiLimitError`) with a stable `code` from typed unions, registered in `docs/data/errors.json`; eleven CWE-tagged `PkiLimits` with `DEFAULT_PKI_LIMITS`, mirrored in `docs/data/limits.json` and SECURITY.md; the single diagnostics channel (`strict`, `onDiagnostic`, `console.warn` once per code in each call) with one payload factory per code, registered in `docs/data/diagnostics.json`; strict UTF-8, UCS-2, UCS-4 and ASCII-subset text codecs; canonical base64. `verify:docs` gains `error-parity` (including the message prefix of every throw site), `diagnostics-parity` and `limits-parity`.

- **chore: bootstrap** — build (tsup ESM + CJS + declarations, a single entry point with `browser`, `import` and `require` conditions), three strict tsconfigs, ESLint 9, vitest 4 with coverage thresholds, the quality gate (`scripts/gate.ts`), the documentation and governance verifier (`scripts/verify-docs.ts` with one module per rule family and a perturbation test per rule), the architecture test that enforces the layer table and the syntactic conventions from the syntax tree, hardened CI on Linux and Windows, CodeQL, Scorecard, Dependency Review, weekly audit, an inert pre-1.0 publish workflow, rulesets, the human-in-the-loop AI governance policy, the Claude Code guard hook and generated rules, and the contributor documentation.
