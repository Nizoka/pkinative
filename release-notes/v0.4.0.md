# pkinative v0.4.0

<!-- GitHub Release title: v0.4.0 — prove what it writes, not only what it reads -->

_Released 2026-09-25_

Milestone M2b. **No new public export, and no engine behaviour changed** except one: `subjectAltName` can now name an IP address and a registered ID. Everything else in this release is evidence — the machinery that decides whether the 0.3 creation surface is right, and whether the parser is right for the reasons it claims. Additive for anyone on v0.3.0.

## Highlights

- **Conformance level L5** — RFC 5280 checked clause by clause by an engine-independent reader. The gate stops being a regression detector and starts attributing violations to sentences.
- **The write direction** — foreign tools reading what pkinative produces, blocking on Linux, Windows and macOS. There is no corpus for this direction; the tools are the oracle.
- **An output-byte baseline** — 24 artefacts hashed against a reviewed file, because an encoder can drift with every structural test still green.
- **A performance trend** — `bench.yml`, archived weekly, never a threshold.

## Added

- **feat(conformance):** conformance level **L5**. 19 clauses of RFC 5280 §4.1 and §4.2 in `scripts/lib/clauses.ts`, each quoting its normative sentence and naming the diagnostic that must report it; `scripts/validators/rfc5280-clauses.ts` decides each from raw bytes without importing `src/`. The runner fails on a violation pkinative is silent about, and — for a clause that claims to decide every case its diagnostic covers — on a diagnostic with no violation behind it. First run over 29 797 parsed certificates: 8 clauses violated across 15 readings, **every one attributed**.
- **feat(conformance):** the **write direction** (`npm run interop`). OpenSSL 4.0.0 and Windows CryptoAPI read every artefact pkinative writes and agree on the serial, the subject, the DNS names, the chain and the request's self-signature. It runs inside the `conformance` job, whose three contexts the ruleset already requires.
- **feat(conformance):** an **output-byte baseline** (`npm run verify:samples`). 24 samples, from a single `AlgorithmIdentifier` to a signed chain and a PKCS#10 request, hashed against `scripts/data/output-bytes.json` where each entry records the release its hash came from. Signed samples use Ed25519 from a fixed seed — deterministic by RFC 8032, with no key committed.
- **feat(bench):** `bench.yml`, a weekly trend with the run context written into the artefact beside the numbers. Benchmarks for the 0.3 creation paths, and `bench-parity` to keep the record attributable.
- **feat(build):** `subjectAltName` can name an **IP address** and a **registered ID**; the union is the exported `GeneralNameDescription`.
- **docs:** an `interop_report.md` issue template, because the write direction carries a different burden of proof.

## Changed

- **refactor(gate):** three steps join it — `verify:samples` (fast, CI and publish), `interop` (publish). The CI profile is 12 steps, publish is 14.
- **refactor(tests):** `--level` defaults to 5 in `scripts/validate-certs.ts`. L5 is additive: no level was renumbered, because the numbers are cited in CI, the docs and `--level N`.

## Fixed

- **fix(tests):** a fuzzing suite was one busy runner away from a flake nobody could reproduce. The string-confusion search called `expect` 45 000 times inside its hot loop and vitest builds an assertion object per call; three quarters of its 12 s was bookkeeping, and under load it crossed the implicit 30 s timeout. Mismatches are collected and asserted once, the budget is now explicit, and the whole `test` step went from 100 s to 31 s on every run, on three operating systems.

## Performance

`bench/RESULTS.md` carries a dated section for 0.3.0 on an idle machine. The parsing rows are **not** comparable with the 2026-09-19 section, which ran under load; the section says so rather than presenting a 72 % improvement that is nothing but the load difference. `createCertificate` measures 2 888 ops/s, of which an ECDSA P-256 signature is roughly 90 % — the row is labelled so nobody quotes it as pkinative's signing speed.

## Conformance

Corpus pins unchanged: x509-limbo at `1187213` (9 793 cases, 30 361 certificates, 564 reviewed refusals), Wycheproof at `3fa63dd` (1 530 vectors). L5 adds 19 clauses, 17 exercised by the corpus and 2 waived to `tests/conformance/clauses.test.ts` with the reason written down — x509-limbo holds no certificate with a unique identifier and none with a multi-valued RDN, because neither bears on path validation.

## Documentation

- **docs(guides):** `conformance.md` gains L5 and the write direction, including why a tool this runner cannot parse is never evidence about the artefact.
- **docs(security):** SECURITY.md records the coverage-guided fuzzing added in 0.3 and states plainly that the container has never executed.

## Known limitations

- **Five of seven interop tools are declared and not written.** GnuTLS `certtool`, Windows `certutil`, `keytool`, macOS `security` and Python `cryptography` are listed in `scripts/lib/interop.ts` with the reason each is pending. `--require-all`, which turns a missing tool into a failure, goes on in the commit that lands the last of them. Two independent lineages check every artefact today; that is not six.
- **L5 covers RFC 5280 §4 only.** §6 roughly doubles the table and arrives with path validation in 0.5. The completeness assertion becomes blocking at 0.9.
- **The ClusterFuzzLite workflow has still never executed.** This repository has no pushed history. The targets are proved locally against `src/` on every gate run; the container wiring is not proved at all.
- **No chain is validated, and no revocation is checked.** 0.5.0.

## Downstream integration notes

- **One new type, one widened input, nothing removed.** `GeneralNameDescription` is exported, and `encodeSubjectAltName` accepts two more `kind` values: `iPAddress` (a `Uint8Array` of 4 or 16 octets, network byte order) and `registeredID` (a dotted OID string). Existing calls compile and produce identical bytes.
- **`iPAddress` takes bytes, not text.** The same rule as `issuerDer`: `2001:db8::1` and `2001:0db8:0000:0000:0000:0000:0000:0001` are two spellings of one address, and a certificate that names the wrong host because a `::` expanded differently is not a bug anyone finds quickly. Four and sixteen octets only — the 8- and 32-octet forms carry a mask and belong to `nameConstraints`.
- **New npm scripts and gate steps.** `verify:samples` and `interop`. A downstream fork running `npx tsx scripts/gate.ts --publish` gets two more steps; `interop` shells out to whatever is installed and is publish-only for that reason.
- **`scripts/data/output-bytes.json` is a new reviewed baseline.** A change to any encoder moves it, and that is a diff a human reads before it is blessed — like `limbo-refusals.json`, never hand-edited.
- **The three machine contracts for the satellites are unchanged**: `docs/assets/api.json`, `docs/data/errors.json` and `docs/data/diagnostics.json`.
