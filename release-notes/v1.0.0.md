# pkinative v1.0.0

<!-- GitHub Release title: v1.0.0 — the freeze, promised -->

_Released 2026-09-29_

Milestone M6, and the first release of pkinative: on npm with provenance, and on GitHub with an attested tarball. Versions 0.1 to 0.9 were git tags only, never released, so nothing needs migrating unless you built from one of them. 1.0.0 adds no engine behaviour over 0.9.0 except one deliberate change: `openPkcs12` no longer guesses an RSA key's signature scheme (see **Upgrade**). What it adds is a promise. For the whole 1.x line, the export surface, the error vocabulary and the decision surface (which certificates pkinative refuses, and with which code) change only in ways semantic versioning allows. Each of those three parts is recorded in a committed snapshot and held by a rule that fails the build.

## Highlights

- **The compatibility promise, in three parts.** [SECURITY.md §Compatibility promise](../SECURITY.md#compatibility-promise) states what 1.x keeps, and `ecosystem.json → contracts.compatibility` states it for machines:
  - **The export surface.** Every export keeps its name, its kind and a compatible signature, and every `PkiReasonCode` stays. Held by `docs/assets/api.frozen.json` and the `api-surface-frozen` rule.
  - **The error vocabulary.** The 57 `PkiErrorCode`s keep their names and classes, as they have since 0.8.0. Held by `docs/data/errors.frozen.json` and `error-codes-frozen`.
  - **The decision surface.** Each of the 565 x509-limbo certificates pkinative refuses stays refused with the same code; a new refusal is a recorded fix; every corpus certificate re-encodes byte for byte. Held by `docs/data/refusals.frozen.json`, `refusal-baseline-frozen` and conformance levels L1 and L2 ([ADR 0014](../docs/adr/0014-the-decision-surface-contract.md)).
- **The publication path hardened before its first use:**
  - `publish.yml` publishes only from a `v*` tag that matches `package.json`, and refuses anything below 1.0.0 before any approval is asked.
  - It publishes through npm Trusted Publishing (OIDC, no stored token) with provenance, after the full publish gate.
  - It then fetches the tarball back from the registry and attests it, so the file attested on GitHub is the file npm serves.
  - Neither release job restores a dependency cache.
- **The tarball checked file by file.** `docs/data/package-files.json` lists the twelve files the package ships, with each one's executable bit and the SHA-256 of the licence files; `check:package` fails on any other file.
- **No default RSA scheme** ([ADR 0015](../docs/adr/0015-no-default-rsa-scheme.md)). A default frozen at 1.0 could not change for the whole major line; one added in a later minor breaks nobody.

## Breaking Changes

- **BREAKING (from 0.9.0): `openPkcs12` opens an RSA key only with the scheme you name.**
  - An `rsaEncryption` certificate does not say whether its key signs with PKCS#1 v1.5 or PSS, nor with which hash. The key is unwrapped non-extractable, so a wrong guess could not be corrected afterwards.
  - Without `options.rsaAlgorithm`, an RSA key now stays closed: the report is `valid: false` with the new reason `PKI_REASON_PKCS12_RSA_SCHEME_UNSPECIFIED`, and the file's certificates, CRLs and other keys are still reported.
  - `importPrivateKey` already refused to guess an RSA scheme.

## Added

- **feat(verify):** `PKI_REASON_PKCS12_RSA_SCHEME_UNSPECIFIED` (RFC 8017 §8), the 43rd reason code.
- **feat(verify-docs):** new rules:
  - `refusal-baseline-frozen` and `contracts-shape`;
  - `package-files-parity`, for the tarball manifest.
- **feat(release):** new release tooling:
  - `build-refusals-frozen.ts`, with `--ratchet`, `--major` and `--repin`.
  - `release-prepare.ts` rebases or ratchets all three snapshots.
  - `release-prepare.ts` also swaps the reviewed pre-1.0 prose table (`PRE_1_0_PROSE`) for its stable-era text at the 1.0.0 bump.
- **docs(adr):** [0014](../docs/adr/0014-the-decision-surface-contract.md), the decision surface, and [0015](../docs/adr/0015-no-default-rsa-scheme.md), no default RSA scheme. Fifteen records in all.

## Changed

- **docs:** the install is `npm install pkinative` everywhere. README, the quick start, the agent brief and the landing page say pkinative is stable and on npm, with the attested GitHub tarball as the alternative.
- **docs(security):** SECURITY.md is restructured around:
  - the compatibility promise;
  - what stands in place of an external audit, with each scanner named on the trigger it actually runs on;
  - release integrity.

  Supported versions: the latest 1.x minor.
- **chore(release):** `release-assets.yml` is retired. It attested the tarball of a pre-1.0 GitHub release, and there are none.

## Conformance

Unchanged from 0.9.0, which is the point: the promise is made on the verdicts 0.9 already gave.

- **L1** — 565 refusals now held to the frozen snapshot, code for code.
- **L2** — every corpus certificate re-encodes byte for byte.
- **L5** — 25 clauses against the pinned text of RFC 5280.
- **L6** — x509-limbo, 9 156/9 208.
- **L7** — NIST PKITS, 195/203.
- **L8** — S/MIME: 221/224 intact, 196/204 agree with NIST.
- **Interop** — OpenSSL 4.0.0 and Windows, in both directions.

## Known limitations

- **No external security audit** ([ADR 0010](../docs/adr/0010-no-external-security-audit-at-1-0.md)). What stands in its place is listed in [SECURITY.md](../SECURITY.md#in-place-of-an-external-audit). If you need an audit for procurement, open an issue.
- **Promised for the default options only.** The promise does not cover diagnostic severity or wording, error message wording, limit default values (which may be lowered in a minor), path, revocation and CMS verdicts (recorded, not frozen), scores, bundle sizes or performance.
- **A PKCS#12 key whose certificate names `id-RSASSA-PSS`** is still reported `PKI_REASON_PKCS12_KEY_UNSUPPORTED`. Taking the scheme from its parameters would be a later, compatible addition.
- **37 RFC 5280 §4 requirements** that could be decided from one certificate are not diagnosed; they are listed in `scripts/data/rfc5280-requirements.json`.
- **Mutation testing** is run by hand on the security-critical modules, not in the gate.
- **ClusterFuzzLite has not yet run on GitHub**, because the repository is published with this release.

## Upgrade

**From nothing:** there was no previous release, so this is the first install.

**From a 0.9.0 build of the tag:** one change.

- If you open an RSA `.p12`, name the scheme you used to get implicitly:

  ```ts
  const report = await openPkcs12(p12Bytes, { password, rsaAlgorithm: { name: 'RSASSA-PKCS1-v1_5', hash: 'SHA-256' } });
  ```

- Without it, an RSA key comes back `undefined`, with `PKI_REASON_PKCS12_RSA_SCHEME_UNSPECIFIED` in `report.reasons`.
- Code that checks `report.valid` already fails closed.

## Downstream integration notes

- **The machine contracts, for the satellites to come.** `pkinative-cli` and `pkinative-mcp` will be built on these, and so can anything else:
  - **`docs/assets/api.json`** — every export, its module, signature and TSDoc. Its surface is frozen by `docs/assets/api.frozen.json`.
  - **`docs/data/errors.json`** — every thrown code, with when it is raised, its remedy, its standard and its CWE. Frozen since 0.8.0 by `docs/data/errors.frozen.json`.
  - **`docs/data/reasons.json`** — every returned reason code. Frozen with the export surface.
  - **`docs/data/diagnostics.json`** — the 40 diagnostic codes. Additions only; severity and wording may change.
  - **The report types.** `verifyCertificateChain`, `openPkcs12`, the CMS and timestamp reports: frozen as part of the export surface.
  - **`ecosystem.json → contracts.compatibility`** — the three parts of the promise, the snapshot and rule for each, and what is not promised.
- **New reason code:** `PKI_REASON_PKCS12_RSA_SCHEME_UNSPECIFIED`.
- **Behaviour shift:** `openPkcs12` without `rsaAlgorithm` no longer opens RSA keys.
- **No export added, removed or changed:** 282 exports. No error code or diagnostic code changed.
- **Semver from here:**
  - A minor release only adds.
  - A newly refused corpus certificate is a recorded fix: its release note lists it under `### Decision surface`.
  - A removal, a changed code or an incompatible signature waits for 2.0.0.
