# pkinative v0.9.0

<!-- GitHub Release title: v0.9.0 — the freeze, rehearsed -->

_Released 2026-09-29_

Milestone M5b. This release adds nothing a caller asked for and exists to prove that 1.0 can promise what it will promise. The public surface is snapshotted and a rule fails on any change to it; every name that freezes at 1.0 was audited, and the ones a 1.0 would regret were renamed now, while that costs a minor. The work found two paths pkinative accepted and RFC 5280 rejects, and both are fixed. **This release renames exports, fields, limits and one reason code, with no aliases** — see **Upgrade** and **Downstream integration notes** before moving from 0.8.0.

## Highlights

- **The freeze, made executable.** `docs/assets/api.frozen.json` records every export's kind and a signature read from the syntax tree; `api-surface-frozen` fails on any change to it in this phase, and on any incompatible one from 1.0. It moves only through `build-api-frozen.ts --rebaseline` on an accepted ADR, which logs the move. Error codes now ratchet: a code a 1.x release ships stays a promise.
- **The rename set, landed once** — [ADR 0013](../docs/adr/0013-renames-before-the-freeze.md) holds the table and what was deliberately left.
- **Two acceptance defects closed.** An `rfc822Name` constraint now reaches a subject `emailAddress` when there is no subjectAltName (RFC 5280 §4.2.1.10) — the real cause of NIST's `InvalidDNandRFC822nameConstraintsTest29`, a deviation from 0.5.0 to 0.8.0. And an excluded `directoryName` now matches after §7.1 preparation.
- **Completeness against the RFC.** RFC 5280 is pinned as a corpus: every L5 quote must be verbatim, and every requirement sentence of §4.1–§4.2 is a clause or a reviewed exclusion. Four quotes the RFC does not contain were found — one invented.
- **Mutation testing, and the decisions written down** — the eight security-critical modules at 100 % mutation score; thirteen architecture decision records.

## Changed

- **refactor!:** the rename set. Limits: `maxCmsAttributes` → `maxAttributes`, `maxCmsBagEntries` → `maxCmsCertificatesAndCrls`, `maxOcspResponses` → `maxOcspSingleResponses`. Report field `verified` → `signatureVerifications` (a count that read like a boolean). Input fields `ocsp` → `ocspResponses`, `responderAuthorised` → `responderAuthorized`, `requiredPurposes` → `purposes`, `ValidateCertificatePathInput.certificates` → `path`, `requireExplicit` → `requireExplicitPurpose`, `allowNonCriticalTimestampingEku` → `allowNonCriticalTimeStampingEku`; `CheckRevocationInput.options` flattened into `limits` and `onDiagnostic`; `PrivateKeyInfo.namedCurve`/`keyType` → `curve`/`kind`. Functions `signatureAlgorithmDer` → `encodeSignatureAlgorithm`, `dnsMatches` → `matchDnsName` (with `MatchDnsNameOptions`), `encodeCertId` → `encodeOcspCertId`, `readPkcs12` → `openPkcs12`. Reason `PKI_REASON_UNRECOGNISED_CRITICAL_EXTENSION` → `PKI_REASON_UNKNOWN_CRITICAL_EXTENSION`. And the types that broke *function name plus `Input`, `Options` or `Report`* — `VerifyChainInput` → `VerifyCertificateChainInput` and the rest, listed in the ADR.

## Added

- **feat(verify-docs):** `api-surface-frozen`, `release-era-prose` and `adr-index`; `build-api-frozen.ts` with `--rebaseline`, `--ratchet` and `--major`; `build-errors-frozen.ts --ratchet`; `check-npm-drift.ts`, run weekly and online.
- **feat(conformance):** RFC 5280 pinned as a corpus; `scripts/data/rfc5280-requirements.json` accounts for all 182 requirement sentences of §4.1–§4.2; six new L5 clauses for requirements pkinative already diagnosed (25 in all).
- **test(mutation):** `npm run mutate`, a deterministic, dependency-free mutation runner, and the 19 tests its survivors asked for.
- **docs(adr):** thirteen decision records in `docs/adr/`.
- **PKI_DIAG_CRL_EXTENSION_MALFORMED** — a CRL extension no verdict depends on, dropped because it is malformed, is now diagnosed.

## Fixed

- **fix(path):** an `rfc822Name` constraint was not applied to the subject `emailAddress` of a certificate without a subjectAltName, so a path the constraint forbids was accepted. NIST PKITS 194 → 195/203, S/MIME 195 → 196/204.
- **fix(path):** a subject differing from an excluded `directoryName` subtree only in case, spacing or string type escaped it. No corpus case reached it. Permitted subtrees keep byte comparison, whose failure mode is a refusal.
- **fix(revocation):** a malformed `cRLNumber`, delta indicator, reason code or invalidity date vanished without a word, and a programming error would have too; every catch in `src/` now passes what it caught through one guard that re-throws anything that is not a `PkiError`.
- **docs:** the 0.5.0 and 0.7.0 notes said no deviation accepts what a standards body rejects — Test29 did, and the notes now give its real cause. "`verify/` is the only place that catches a `PkiError`" is corrected to what holds: it is the only layer that turns one into a reason. The choice guide describes what ships.

## Conformance

- **L5** — 25 clauses, against the pinned text of RFC 5280: 182 requirement sentences, 21 held by a clause, 161 excluded with a reviewed reason, none unaccounted for; every quote verbatim. 37 requirements decidable from one certificate are recorded as not yet diagnosed.
- **L6** x509-limbo 9 156/9 208 (99.44 %), unchanged. **L7** NIST PKITS 195/203 (96.06 %), eight deviations, five of them RFC 5280 §7.1 name comparison and every one a refusal. **L8** S/MIME 221/224 intact, 196/204 agree with NIST, 204/204 equal to their path verdicts.
- **Interop** unchanged: OpenSSL 4.0.0 and Windows, both directions.

## Known limitations

- **The rehearsal fell short of "zero" in three stated places:** one exported type added (`MatchDnsNameOptions`, required by the rename set), one diagnostic added, and three engine changes, all fixes. No error or reason code was added.
- **37 RFC 5280 §4 requirements** that could be decided from one certificate are not diagnosed; they are listed in `scripts/data/rfc5280-requirements.json` under `not-diagnosed`.
- **Mutation testing** sampled the two largest modules rather than exhausting them, and 300 of 819 mutants were refused by the type checker, so those guards are held by types rather than tests. It is not part of the gate: a full run takes about 43 minutes.
- **ClusterFuzzLite has still never executed.**

## Upgrade

**Not a drop-in replacement for v0.8.0.** Every rename is a rename, with no alias: a TypeScript build names each place to change, and plain JavaScript that reads `report.verified`, passes `ocsp:` or sets a renamed limit silently gets `undefined` or an unknown-limit error (`PKI_LIMIT_INVALID`), so search for the old names. The table is in [ADR 0013](../docs/adr/0013-renames-before-the-freeze.md). One output changed with a rename: the path of a malformed stapled OCSP response is `ocspResponses[n]`, not `ocsp[n]`.

## Downstream integration notes

- **Renamed, no aliases:** the full old → new table is ADR 0013. Error codes and diagnostic codes are untouched; one reason code changed (`PKI_REASON_UNRECOGNISED_CRITICAL_EXTENSION` → `PKI_REASON_UNKNOWN_CRITICAL_EXTENSION`), so a caller branching on it must update.
- **New public API:** `MatchDnsNameOptions`, the options type `matchDnsName` takes. 282 exports.
- **Behaviour shifts:** a certificate without a subjectAltName whose subject `emailAddress` falls outside a permitted `rfc822Name` subtree, or inside an excluded one, is now refused with `PKI_REASON_NAME_NOT_PERMITTED` or `PKI_REASON_NAME_EXCLUDED`; a subject matching an excluded `directoryName` only after §7.1 preparation is refused with `PKI_REASON_NAME_EXCLUDED`. Both were accepted before and should not have been.
- **New diagnostic:** `PKI_DIAG_CRL_EXTENSION_MALFORMED`.
- **The contract that holds from here:** error codes are frozen (0.8.0); the public surface is frozen for 0.9 and becomes the 1.0 contract; diagnostic codes are additions-only, and their severity and wording may change; limit names freeze at 1.0.
