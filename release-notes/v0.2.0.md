# pkinative v0.2.0

> This version was prepared and never released — no tag, no GitHub Release, nothing on npm: the install instructions below describe a release that was not made.

<!-- GitHub Release title: v0.2.0 — hardened, held to three platforms, and runnable on its own site -->

_Released 2026-09-20_

v0.2.0 adds no public export and changes no decoded value: the engine of v0.1.0 is the engine of v0.2.0, and every one of the 127 exports keeps its signature. What changed is everything around it — the proof. Coverage is 100 % on all four axes by construction; the conformance gate gained a level that confronts pkinative with an implementation written by other people; CI verifies Linux, Windows and macOS; the built package is probed as an artefact rather than trusted as a syntax tree; and the site is now the third copy of the family charter, with two playgrounds that run the published build on bytes you choose. **100 % backward-compatible with v0.1.0.**

## Highlights

- **Conformance level L4 — cross-implementation confrontation.** There is no veraPDF for the PKI, so the gate confronts instead: 202 sampled x509-limbo certificates are read again by Microsoft CryptoAPI through .NET `X509Certificate2`, and the readings must agree on SHA-256 of exact DER slices. 202 of 202 agree on all five fields. Three guards — a positive canary, four broken canaries, a completeness footer — make agreement mean something, and none can be waived.
- **100 % branch coverage, by removing the branches.** Of 63 uncovered branches, 60 were `?? fallback` expressions that `noUncheckedIndexedAccess` forces after a bound the code has already proved; they are gone with the code that created them. Two remain, each with a justified `v8 ignore` counted by a rule.
- **Linux, Windows and macOS, all required.** `macos`, `conformance-windows` and `conformance-macos` are purely additive — no existing status-check name was renamed, which is what otherwise leaves every pull request waiting on a context that will never report again.
- **The library runs on its own site.** Two playgrounds decode a certificate and walk its ASN.1 tree in the browser, on a byte-for-byte copy of what `npm run build` produces, held to it by a rule in two layers. Both treat a refusal as a result: the `PkiError` comes back with its code, its subclass and its offset.
- **A forensic probe of what `dist/` ships.** The `bundle-check` gate step decides on the artefact — no `node:` specifier, no package, `console` reached exactly once, no fixture marker, no embedded PEM, both declaration files naming every export, every file inside a declared byte budget.

## Added

- **feat(conformance):** level L4, cross-implementation confrontation, with per-validator field masks, VACUOUS/XPASS canaries and a completeness footer; disagreements recorded in `scripts/data/validator-disagreements.json`, empty today.
- **feat(build):** `scripts/lib/bundle-probe.ts` and the `bundle-check` gate step; `build` and `dist-check` now run before the suites so the probe has an artefact, and `test:coverage` sets `GATE_REQUIRE_ARTIFACTS` so a missing `dist/` fails instead of silently skipping a suite.
- **feat(docs):** two playgrounds under `docs/playground/` — a certificate inspector and an ASN.1 tree — plus `scripts/build-playground.ts`, which copies `dist/index.js` byte for byte because pkinative is not on npm before 1.0.0 and there is no CDN to load it from.
- **feat(docs):** a sixth guide, `use-cases`, and a generated `docs/sitemap.xml` derived from the canonical URL each page declares.
- **feat(ci):** `macos`, `conformance-windows` and `conformance-macos`; `ruleset-parity` now derives check names the way GitHub does, `include:` entries included.
- **feat(docs):** sixteen new verify-docs rules, among them `clean-url-safe`, `social-images`, `cdn-sri`, `chrome-parity`, `coverage-ignore-budget`, `playground-freshness`, `export-named`, `member-tsdoc`, `extension-kinds-complete`, `option-fields-named` and `surfaces-parity` — plus the `docs:playground-fresh` gate step. **33 rules become 49**, each with a perturbation row that proves it fails when it should.

## Changed

- **refactor(core):** 60 defensive `?? fallback` expressions removed with the code that required them — a `DataView` per decode call, `for…of` in place of indexed loops, `charAt`, `match[0]` in the PEM grammars, `tagClassOf` in place of an indexed tag-class table.
- **chore(release):** `release-prepare.ts` gains the six install-URL rewrites it was missing. Before them every release failed `install-url-version`, a rule inside `verify:docs`, and was patched by hand.
- **docs(roadmap):** a 0.4 band for interoperability and clause checking; the error-code vocabulary freezes at **0.8**, not 0.9, with 0.9 becoming the rehearsal; 1.0 no longer promises an external audit or the satellites.

## Fixed

- **fix(x509):** `formatDistinguishedName` printed `,,` for an entry that is not an array of attributes. It now throws `PKI_INVALID_INPUT`, as every other wrong argument does.
- **fix(docs):** `og:image` and `twitter:image` pointed at an SVG, which no social platform renders, so every share card was blank. Both are now committed PNGs with declared dimensions.
- **fix(docs):** under `cleanUrls` the link `guides/index.html` took two redirects and landed on a URL whose base directory is the site root, so the guides index loaded without its stylesheet.
- **fix(core):** `firstOctetOutside` returned an index where its contract promised the octet. Internal; no public export changes.

## Performance

- **perf(asn1):** `isValidOid` is a grammar alone — the second-arc bound moved into the expression, so the `split` and the `BigInt` on the `decodeExtensionValue` path are gone. Verified equivalent against the previous predicate over 200 457 generated candidates before the old one was deleted.

## Conformance

- Corpora unchanged: x509-limbo at `118721335e67`, Wycheproof at `3fa63dd0344a`, both pinned by commit and SHA-256. 30 361 unique certificates, 9 793 test cases, 564 refused, 1 530 ECDSA vectors — every figure identical to v0.1.0, which is the point: no decoded value moved.
- Level L4 added. Levels L0–L3 unchanged.
- No SUCCESS/FAILURE score is claimed. pkinative validates no path before 0.5.

## Documentation

- **docs(site):** style.css 118 → 704 lines, guide.css 21 → 298; 115 classes against zipnative's 120. The mark becomes the family tile with a key, and both social cards adopt the family grammar.
- **docs(agents):** the agent brief names all twenty extension kinds, and its sample is a function that runs.

## Known limitations

- **No signature verification and no path validation.** A fingerprint proves two byte strings are the same certificate and nothing about whether it should be trusted. Verification through Web Crypto arrives in 0.3, RFC 5280 §6 in 0.5.
- **No CRL, no OCSP, no CMS, no PKCS#8 or PKCS#12.** 0.5, 0.7 and 0.8 respectively.
- **The error-code vocabulary is not frozen yet.** Until 0.8 a code may be renamed or removed in a minor, and every such change is listed under Downstream integration notes.
- **Conformance is differential below the clause checker.** L1–L4 prove agreement with x509-limbo's expectations, `node:crypto`, the `openssl` CLI and a foreign implementation. Nothing here proves pkinative correct where every implementation is wrong together; the clause-by-clause checker that would arrives in 0.4.
- **The playground bundle is committed.** 159 668 bytes of built engine live in `docs/`, because there is no npm package to load from yet. It retires when there is.

## Upgrade

No breaking changes, and no code change is required. Drop-in replacement for v0.1.0.

One behaviour is stricter, and it can only affect a caller that was already receiving nonsense: `formatDistinguishedName` throws `PKI_INVALID_INPUT` for an `rdns` that is not an array of attributes, where it previously returned a string of commas. A caller passing a real `DistinguishedName` is unaffected.

## Downstream integration notes

- **No public API change.** 127 exports, identical signatures. `docs/assets/api.json` is byte-identical apart from the version it records.
- **No new error code and no new diagnostic code.** 44 error codes, 26 diagnostic codes, unchanged. The `docs/data/errors.json` and `docs/data/diagnostics.json` registries move their freeze statement from 0.9.0 to 0.8.0; nothing in either registry changed.
- **No limit and no limit default changed.** 11 named, CWE-tagged limits.
- **One behaviour shift**, above: `formatDistinguishedName` on a malformed `rdns`.
- **New machine-readable surface for consumers:** `declared.playgroundBundle` and `declared.bundle` in `docs/assets/ecosystem.json`, and `contracts.error_codes_frozen_since` now reading `0.8.0`.
