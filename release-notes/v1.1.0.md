# pkinative v1.1.0

_Released 2026-11-18_

The first minor of the 1.x line: additive under the compatibility promise, 100 % backward-compatible with v1.0.0 — the v1.0.0 test suite passes, as tagged, against these sources (`compat-previous`). It verifies ML-DSA signatures where the host does, reads back the two requests it writes, gives the verify and check verbs `strict`, and hardens the repository around the engine: Node.js 26, a release path that fails without its files, and the tooling that keeps the satellites' documentation aligned.

## Highlights

- **Post-quantum signatures verified.** ML-DSA-44/65/87 (FIPS 204) on certificates, CRLs, OCSP responses, certification requests, CMS signers and timestamp tokens, on a runtime whose Web Crypto has the algorithm (Node.js 24.7 and later); elsewhere the verdict says the signature was not checked, never that it is valid. SLH-DSA and ML-KEM public keys are read as kinds of their own.
- **Attribute certificates read.** RFC 5755 attribute certificates are parsed and their signature checked; their validation (§5) is left to the caller, and the recipe shows the composition.
- **The requests pkinative writes can be read back**: `parseTimeStampRequest` (RFC 3161) and `parseOcspRequest` (RFC 6960, with the RFC 9654 nonce).
- **`strict` reaches the verify and check verbs**, and `verifySignedData` reports its diagnostics.
- **Node.js 26 is a supported line**, tested by a required check.
- **The 1.x promise is run, not only stated**: the previous release's own test suite is a required check on every pull request.

## Security

- **chore(deps-dev): eight advisories in the test toolchain closed** — vitest 4.1.12 and vite 8.2.6 (GHSA-587h-7wmj-h5pm, high, and seven more), and four in the Python interoperability pin (`pyasn1` 0.6.5). Development-only: the published package has no dependency. `picomatch` ≤ 4.0.7 (GHSA-fc5q-39xc-vjpf), reached through the test and build tools, has no patched release at the time of writing.
- **fix(agents): the guard hook resolves from `$CLAUDE_PROJECT_DIR`** ([#13]): by a relative path it stopped guarding once the shell left the repository root.
- **fix(release): a release without its files is a red run** ([#14]): the attest job fails when the release cannot be read, reads the five file names back and fetches the tarball from its public URL against the build digest; `check-npm-drift` holds the GitHub release to the same files every week. The `v1.0.0` release was published without its files attached.

## Added

- **feat(crypto): ML-DSA verification, host-dependent** ([ADR 0026](../docs/adr/0026-ml-dsa-verified-where-the-host-verifies-it.md)). Pure ML-DSA with an empty context, as RFC 9881 requires in PKIX; for a CMS signer, the digest rule of RFC 9882. One Web Crypto call, like every other signature: no post-quantum arithmetic in TypeScript.
- **feat(x509): SLH-DSA and ML-KEM public keys** read as their own kinds, with their lengths checked.
- **feat(x509): `PKI_DIAG_KEY_USAGE_KEY_ALGORITHM_MISMATCH`** (warning): a keyUsage a post-quantum key's algorithm does not allow.
- **feat(keys): `parsePrivateKeyInfo` names an ML-DSA private key**; `importPrivateKey` still refuses it.
- **feat(x509, crypto): RFC 5755 attribute certificates read and signature-checked** ([ADR 0028](../docs/adr/0028-attribute-certificates-are-read-not-judged.md)) — `parseAttributeCertificate` (holder, issuer, the six attributes of §4.4, the AC-only extensions; the profile reported through 9 `PKI_DIAG_AC_*` diagnostics; one new error code, `PKI_X509_ATTRIBUTE_MALFORMED`) and `verifyAttributeCertificateSignature`. RFC 5755 §5 validation is not implemented: there is no `verifyAttributeCertificate`.
- **feat(cms): `parseTimeStampRequest`** → `TimeStampRequest`.
- **feat(revocation): `parseOcspRequest`** → `OcspRequest`, `OcspRequestEntry`, `OcspRequestSignature`; the nonce is accepted on 1 to 128 octets (RFC 9654 §2.1). Three diagnostics: `PKI_DIAG_OCSP_REQUEST_SIGNED_UNNAMED`, `PKI_DIAG_OCSP_NONCE_LENGTH`, `PKI_DIAG_OCSP_REQUEST_EXTENSION_CRITICAL`.
- **feat(verify): `strict` on the verify and check inputs, a diagnostic sink on `verifySignedData`** ([#18], [ADR 0025](../docs/adr/0025-strict-in-the-verify-and-check-verbs.md)). In a composition (`verifyCertificateChain`, `verifyTimeStampToken`, `verifySignedData`, `openPkcs12`) a warning refused under `strict` is `valid: false` with `PKI_REASON_INPUT_MALFORMED` carrying `errorCode: 'PKI_STRICT_DIAGNOSTIC'`, never an exception; in a primitive (`checkRevocation`, `checkOcspStatus`) it throws `PKI_STRICT_DIAGNOSTIC`.
- **feat(x509): `PKI_DIAG_SPKI_ALGORITHM_UNRECOGNISED`** ([#17], info): a public key whose algorithm pkinative does not classify is still kept, and now reported.
- **ci: Node.js 26 in the matrix and the required checks; `reuse lint`; `compat-previous`; an advisory `Mutation` workflow** for the `src/` files a pull request changes.
- **chore(tooling): satellite alignment** — `npm run satellites:sync`, the `/satellite-align` skill and the rule `satellite-stamps`.
- **chore(conformance): an RFC 5755 §4 requirement inventory** — 69 sentences, 36 held by tests, 33 excluded with a reason.
- **docs(adr):** [0024](../docs/adr/0024-what-a-satellite-may-implement.md) what a satellite may implement ([#15]); [0025](../docs/adr/0025-strict-in-the-verify-and-check-verbs.md); [0026](../docs/adr/0026-ml-dsa-verified-where-the-host-verifies-it.md); [0027](../docs/adr/0027-limit-names-are-closed-in-1-x.md) limit names are closed in 1.x; [0028](../docs/adr/0028-attribute-certificates-are-read-not-judged.md) attribute certificates are read, not judged.

## Changed

- **docs(agents): the always-loaded instructions carry each fact once** ([#12]): 12 680 → 11 147 bytes, under a ceiling lowered from 16 KiB to 12 KiB.
- **ci: the `node-current` workflow is removed** until a Node.js line is Current again (Node 27, 2027-04-22).
- **`engines.node`** is written `^22.22.2 || ^24.14.1 || ^25.8.2 || >=26.0.0`: the same set of versions as 1.0.0.
- **docs(security): the support period of the 1.x line** ([#16]): no end date, an end announced one minor release ahead ([ADR 0017](../docs/adr/0017-runtime-and-toolchain-support.md), amended).
- **docs: the comparison with other libraries re-read from the npm registry on 2026-11-17.**

### Decision surface

No refusal of the frozen corpora moved (`refusals.frozen.json`: 0 new). Outside them:

- **ML-DSA signatures.** 1.0.0 reported `PKI_REASON_SIGNATURE_NOT_CHECKED` with `errorCode: 'PKI_CRYPTO_ALGORITHM_UNSUPPORTED'`. 1.1.0 verifies them where the host can, and elsewhere reports the same reason with `errorCode: 'PKI_CRYPTO_KEY_UNSUPPORTED'`.
- **An ML-DSA CMS signer whose digest RFC 9882 does not allow** is `PKI_REASON_CMS_ALGORITHM_MISMATCH`.
- **A malformed SLH-DSA or ML-KEM public key** (wrong length) throws `PKI_X509_SPKI_INVALID`; 1.0.0 kept it as `kind: 'unknown'`.
- **An ML-DSA private key** is `kind: 'ml-dsa-44' | 'ml-dsa-65' | 'ml-dsa-87'` in `parsePrivateKeyInfo`, where it was `unknown`.
- **`openPkcs12` honours `strict` and `onDiagnostic`**, which its options type already accepted and 1.0.0 ignored: under `strict`, a PKCS#12 that raises a warning is `valid: false`.
- **One more `console.warn` line by default** for a certificate or request whose key algorithm is not classified, and for a post-quantum key whose keyUsage its algorithm does not allow — unless `onDiagnostic` is given.

## Fixed

- **fix(tooling): six code-scanning findings in the scripts and tests** — one `escapeRegExp` for the verify-docs rules, a private temporary directory, a trigger pattern that backtracked polynomially, a script-block filter.
- **docs: two sentences written before the first push** now say what runs.

## Conformance

- RFC 6960: the two request sentences excluded for lack of a reader are now held by tests (20 tested, 3 excluded).
- Interoperability: ML-DSA certificates and CMS cross-checked against OpenSSL 3.5 where it is installed; a tool without ML-DSA is declared absent, not failed.
- RFC 5755: a seventh requirement inventory (§4). No foreign attribute certificate was cross-checked: no graded corpus exists, and the OpenSSL at hand has no attribute-certificate command.
- Fuzz targets: 8 → 11 (`tsp-request`, `ocsp-request`, `attribute-certificate`).
- No positive ML-DSA verdict runs on Node.js 22, the gate's runtime: the `ci (24)` and `ci (26)` legs run it.

## Known limitations

- **ML-DSA is verified, not written**: no ML-DSA signing in the writers and no ML-DSA private-key import (ADR 0026 says when that is revisited). SLH-DSA signatures are not verified.
- **The Certificate Transparency SCT list** is still kept in its TLS encoding.
- **Attribute certificates are read, not judged**: no RFC 5755 §5 validation — holder binding, targeting and AC revocation are the caller's ([ADR 0028](../docs/adr/0028-attribute-certificates-are-read-not-judged.md)).
- **No CRL or OCSP-response writer.**

## Install

```bash
npm install pkinative@1.1.0
npm audit signatures
```

## Upgrade

No export changed or left, and the v1.0.0 test suite passes unchanged: a drop-in replacement for v1.0.0, with one tightening — a malformed SLH-DSA or ML-KEM public key, which 1.0.0 kept as `kind: 'unknown'`, is now refused. Read **Decision surface** above if you branch on `errorCode`, parse PKCS#12 files under `strict`, or assert that parsing emits no diagnostic.

## Downstream integration notes

For pkinative-cli and pkinative-mcp, which pin `pkinative ^1.0.0` and vendor its registries:

- **Registries to re-vendor**: `docs/data/errors.json` (57 → 58 codes: `PKI_X509_ATTRIBUTE_MALFORMED`), `docs/data/diagnostics.json` (97 → 111 codes; `PKI_DIAG_OCSP_VERSION_NOT_V1` now cites "RFC 6960 §4.1.1, §4.2.2.3"), `reasons.json`, `limits.json` (`guards` text only), `defaults.json`, `surfaces.json` (a capability may be `pending` on a satellite), and for the CLI `api.frozen.json` (329 exports) and `errors.frozen.json`.
- **A new error code breaks the CLI's type-check on upgrade**: `src/utils/pkierr.ts` maps every `PkiErrorCode` (`satisfies Record<PkiErrorCode, Mapping>`), so pkinative-cli does not compile against 1.1.0 until it maps `PKI_X509_ATTRIBUTE_MALFORMED`. The published CLI, whose `^1.0.0` pin resolves 1.1.0 on a fresh install, is unaffected at run time: nothing it calls raises the new code.
- **New exports not reached yet**: `parseTimeStampRequest`, `parseOcspRequest`, `parseAttributeCertificate`, `verifyAttributeCertificateSignature` — the CLI's "every runtime export reached" matrix is incomplete until its next minor. Proposed: `tsp inspect-request`, `ocsp inspect-request`; `acert inspect`, `acert verify-signature`; MCP `inspect_timestamp_request`, `inspect_ocsp_request`, `inspect_attribute_certificate`, `verify_attribute_certificate_signature`.
- **`strict`**: both satellites already spread `strict` into `openPkcs12`, so `--strict` on a PKCS#12 with a warning now yields `valid: false`; read `errorCode === 'PKI_STRICT_DIAGNOSTIC'`. The CLI's extra parse in `cms verify` is no longer needed; its `escalateStrict` helper still is, for bag-certificate warnings.
- **ML-DSA**: a verdict that was `PKI_CRYPTO_ALGORITHM_UNSUPPORTED` becomes a verification or `PKI_CRYPTO_KEY_UNSUPPORTED` — update any table of "not checked" causes.
- **`engines.node`** is the same range, written differently; Node.js 26 is a supported line, and `node-current.yml` is gone.
- **Satellite surface contract**: each satellite is asked to commit `docs/assets/surface.json` at release (issue drafts in each repository), which `npm run satellites:sync` reads in contract mode.
