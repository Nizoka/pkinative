# pkinative v0.8.0

> This version was prepared and never released — no tag, no GitHub Release, nothing on npm: the install instructions below describe a release that was not made.

<!-- GitHub Release title: v0.8.0 — private keys, and the vocabulary frozen -->

_Released 2026-09-29_

Milestone M5. pkinative could sign with a key the caller had already imported; this release opens the files keys live in — PKCS#8, encrypted or not, and PKCS#12 — under PBES2 only, and turns each key into a non-extractable `CryptoKey` without an encrypted key's plaintext ever existing in JavaScript. It is also the release at which **the error-code vocabulary is frozen under semantic versioning**: from here, removing or renaming a code, or moving it to another class, is a major version. New exports; nothing removed or renamed. See **Downstream integration notes**.

## Highlights

- **`readPkcs12`** — a `.p12` in one call: the MAC checked where it can be, every SafeContents opened, every certificate parsed, every key unwrapped with its algorithm taken from the certificate sharing its `localKeyId`. It reports and never throws for the file's sake.
- **PBES2 only, by policy, and said so by name.** RFC 7292's own schemes derive their key with Appendix B — iterated hashing with byte arithmetic over the password — and protect it with 3DES or 40-bit RC2. Every such scheme is still described, so a tool can say what a file holds before anyone types a password, and refused with a code whose remedy is a conversion checked against OpenSSL 4.0.0.
- **Integrity fails closed.** Most PKCS#12 MACs are keyed with Appendix B too, so only an RFC 9579 PBMAC1 MAC (OpenSSL 3.4+, `-pbmac1_pbkdf2`) is verified; `readPkcs12` calls anything else invalid unless the caller passes `allowUnverifiedIntegrity`.
- **The vocabulary frozen** — 57 error codes in `docs/data/errors.frozen.json`, held by a rule; and `error-parity` now decides every throw site's code from the syntax tree.
- **Interop, in the read direction** — PKCS#12 and PKCS#8 files written by OpenSSL and by Windows' .NET, opened or refused by name, every opened key checked by the foreign tool.

## Added

- **feat(crypto):** the Web Crypto door opens `deriveKey`, `unwrapKey` and `decrypt`, to its two boundary files only and in its own commit — each returning a handle or public bytes. `canDecrypt` says whether a runtime can open anything at all. `deriveBits`, `encrypt`, `wrapKey`, `exportKey` and `generateKey` stay refused in every version.
- **feat(keys):** a new `keys` layer that never imports `x509`. `parsePrivateKeyInfo` and `parseEncryptedPrivateKeyInfo` describe a key — algorithm, curve, attributes, the v2 public key, the scheme protecting it — with no field holding its secret; `importPrivateKey` and `decryptPrivateKey` return a non-extractable `SigningKey`. `parsePkcs12`, `verifyPkcs12Mac` and `openSafeContents` are the PKCS#12 primitives.
- **feat(verify):** `readPkcs12`, the fourth one-call report.
- **feat(types):** `PkiKeyError` with four `PKI_KEY_*` codes, and `PKI_CRYPTO_DECRYPTION_FAILED`; six `PKI_REASON_PKCS12_*` reasons; `PKI_DIAG_KEY_KDF_ITERATIONS_LOW`; `maxKdfIterations`, checked before the host runs a single iteration, and `maxPkcs12Bags`.
- **feat(docs):** `docs/data/errors.frozen.json` and the `error-codes-frozen` rule; `pkcs12-policy-parity`, holding SECURITY.md's table of what is opened and refused to the code both ways.

## Fixed

- **fix(verify):** a CRL whose envelope parses but whose entry does not made `verifyCertificateChain`, `verifySignedData` and `verifyTimeStampToken` throw; it is reported. And the opposite leak: misuse — a bad limit, a bad option, an argument that is not bytes — was converted into a reason or escaped as a `TypeError`; each report now decides misuse before its first catch. Both found by a seeded fuzzer that now drives every one-call report.
- **fix(keys):** in the files `openssl pkcs12 -legacy` and Windows write, the 3DES-shrouded key was reported as having no certificate; it is reported under its own refused scheme. Found by the interop run.
- **fix(verify):** a plain keyBag a writer nests inside an encrypted SafeContents is plaintext once opened; `readPkcs12` now wipes those bytes after import, and the documentation says so instead of claiming no key is ever in the clear.
- **fix:** `parseTimeStampResponse`, the TimeStampReq reader and `parseCertificateList` say `PKI_INVALID_INPUT` for an argument that is not bytes; a CRL reason names where the caller put the list.
- **fix(verify-docs):** `error-parity` checked a throw site's message and never its code; `count-tokens` read "Twenty-one" as "one".

## Conformance

- **Interop, read direction:** OpenSSL 4.0.0, 45 checks over 13 key containers it wrote; Windows' .NET, 18 checks over 4. Every key pkinative opens signs data OpenSSL or `node:crypto` verifies. What they write by default is recorded: OpenSSL `-export` keys its MAC with Appendix B, Windows exports 3DES, .NET 9's AES export still uses the Appendix B MAC — so a file pkinative can vouch for is one written with `-pbmac1_pbkdf2`, and the documented conversion is checked to produce one.
- **Unchanged:** x509-limbo 9 156/9 208 (99.44 %), NIST PKITS 194/203 (95.57 %), PKITS S/MIME 221/224 intact and 204/204 equal to their path verdicts.

## Known limitations

- **Most PKCS#12 files' integrity cannot be checked here** — only a PBMAC1 MAC can be. That is the cost of not implementing Appendix B, and it is stated in every report as `PKI_REASON_PKCS12_INTEGRITY_UNVERIFIED`.
- **Legacy files are not opened, in any version** — RC2, 3DES and the Appendix B KDF. Convert once: `openssl pkcs12 -in legacy.p12 -legacy -out bundle.pem`, then `openssl pkcs12 -export -in bundle.pem -pbmac1_pbkdf2 -out modern.p12`.
- **`id-RSASSA-PSS` private keys** are refused by every current runtime's Web Crypto and end in `PKI_CRYPTO_KEY_UNSUPPORTED`.
- **A key in a PKCS#12 is matched to its certificate by `localKeyId` only**, and an RSA certificate names the key, not the scheme: `rsaAlgorithm` defaults to PKCS#1 v1.5 with SHA-256.
- **A plain keyBag inside an encrypted SafeContents** is in the clear once opened; the wipe after import is a best effort.
- **pkinative writes neither PKCS#8 nor PKCS#12** — encrypting or wrapping a key is refused by `KEY_OPERATION_POLICY`.
- **ClusterFuzzLite has still never executed.**

## Upgrade

Additive for anyone on v0.7.0: no export was removed or renamed. Two behaviours tighten, both toward the documented contract: the one-call reports throw for misuse they used to turn into a reason, and three parsers throw `PKI_INVALID_INPUT` where they threw a `TypeError` or a length error for an argument that is not bytes.

## Downstream integration notes

- **New public API.** `parsePrivateKeyInfo`, `parseEncryptedPrivateKeyInfo`, `importPrivateKey`, `decryptPrivateKey`, `parsePkcs12`, `verifyPkcs12Mac`, `openSafeContents`, `readPkcs12`, `canDecrypt`, `PkiKeyError`, and the types they refer to. `docs/assets/api.json` lists every export with its module: 281 now, 170 types and 111 values.
- **The error vocabulary is frozen.** `docs/data/errors.frozen.json` is the contract: from 0.8.0, removing or renaming one of its 57 codes, or moving it to another class, is semver-major; adding one is semver-minor. Diagnostic codes are not frozen — a diagnostic is advice, and its severity may change in a minor. Limit names freeze at 1.0.
- **Behaviour shifts.** `verifyCertificateChain`, `verifySignedData` and `verifyTimeStampToken` now throw `PKI_LIMIT_INVALID`, `PKI_INVALID_OPTION` or `PKI_INVALID_INPUT` for misuse they previously reported as `PKI_REASON_INPUT_MALFORMED`, and report a malformed CRL entry they previously threw. `parseTimeStampResponse` and `parseCertificateList` throw `PKI_INVALID_INPUT` for a non-byte argument. CRL reason paths name the caller's index.
- **Passwords.** A string is encoded as UTF-8, which is what OpenSSL and RFC 9579 use; pass a `Uint8Array` for a file written with another encoding. pkinative never modifies a caller's buffer.
- **Layers.** A new `keys` layer (`types, core, asn1, crypto`), which `verify` imports. Describing a key file or a `.p12` ships neither the certificate parser nor the Web Crypto bridge (39.8 KB); `readPkcs12` pays for the parser (94.7 KB). The package is 259.6 KB.
