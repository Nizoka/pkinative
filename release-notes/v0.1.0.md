# pkinative v0.1.0

> This version was tagged, never released: the install instructions below describe a release that was not made.

<!-- GitHub Release title: v0.1.0 — read-only PKI foundation -->

_Released 2026-09-19_

The first milestone (M1) of pkinative: a zero-dependency TypeScript toolkit that reads public-key infrastructure data — strict ASN.1 DER (BER on request), RFC 7468 PEM, object identifiers and complete RFC 5280 X.509 certificates — with CWE-tagged limits, stable error codes and a conformance gate over x509-limbo and Wycheproof. First tagged release; nothing to be compatible with. 0.1.0 is a git tag with an attested tarball attached to its GitHub release, not an npm release; the first npm publication will be 1.0.0.

## Highlights

- **Complete certificate reading.** `parseCertificate` reads every RFC 5280 field and decodes every standard extension; `getExtension` returns one typed; `formatDistinguishedName` writes RFC 4514 strings.
- **Strict by default, safe on hostile input.** DER is decoded as X.690 §10–11 requires, eleven named CWE-tagged limits bound every loop, and every failure is a `PkiError` subclass with a stable code.
- **Diagnostics, not crashes.** What real issuers get wrong is a diagnostic with its RFC section on `certificate.diagnostics`, through `onDiagnostic`, or refused with `strict: true`.
- **Held to external corpora.** All 30 361 unique x509-limbo certificates parse or are refused only where limbo expects failure; all 1 530 Wycheproof ECDSA vectors meet their expectation — every valid signature decodes, every encoding defect is refused; every parsed certificate agrees with OpenSSL.
- **No cryptography it should not own.** No signing, key generation or secret arithmetic in TypeScript; fingerprints hash public data only.

## Security

- DER strictness refuses the ambiguities that make parser differentials (CWE-436): indefinite and non-minimal lengths, constructed strings, non-canonical BOOLEAN, INTEGER and BIT STRING, trailing data.
- The decoder is iterative: `maxDepth` stops hostile nesting (CWE-674) before the call stack does; `maxNodes`, `maxInputBytes` and eight more limits bound the rest.
- Decoded names and OIDs never become object keys (CWE-1321); `formatDistinguishedName` escapes control characters.

## Added

- **feat(core):** the `PkiError` family with typed code unions, `PkiLimits` and `DEFAULT_PKI_LIMITS`, the diagnostics channel (`onDiagnostic`, `strict`); internally, strict text and base64 codecs that the string readers and the PEM decoder use (not exported).
- **feat(asn1):** `decodeAsn1`, `decodeAsn1Sequence`, readers for BOOLEAN, INTEGER, NULL, BIT STRING, OCTET STRING, OBJECT IDENTIFIER, eight string types and both time types, DER encoders, `encodeAsn1Node`, the OID codec.
- **feat(pem):** `decodePem` (strict and lax RFC 7468, `label`) and `encodePem`.
- **feat(hash):** `computeFingerprint`, `computeFingerprintAsync`, `formatFingerprint` over SHA-1, SHA-256, SHA-384 and SHA-512.
- **feat(oid):** `getOidName` and `OID_REGISTRY`, 300+ names with their defining standards.
- **feat(x509):** `parseCertificate`, `getExtension`, `decodeExtensionValue`, `formatDistinguishedName`; public keys checked for RSA, RSASSA-PSS, EC P-256/384/521, Ed25519, Ed448, X25519, X448 and ML-DSA-44/65/87.

## Conformance

- x509-limbo pinned at `118721335e67`, Wycheproof at `3fa63dd0344a`, both by SHA-256 in `.github/checksums/`.
- 564 certificates refused, each used only by x509-limbo test cases that expect failure and recorded in `scripts/data/limbo-refusals.json`.
- No path-validation score is claimed before 0.5.

## Documentation

- **docs:** README, five guides (quick start, security model, conformance, errors and diagnostics, choosing a library), `llms.txt`, `llms-full.txt`, an agent brief, the generated API manifest of 127 public exports, error, diagnostic and limit registries, and six executable recipes.
- **build:** `release-assets.yml` builds every pre-1.0 release from its tag, runs the full gate, packs the tarball, proves it installs and loads as ESM and CJS (`npm run smoke:install`, also a CI gate step), and attaches it with a CycloneDX SBOM and Sigstore build provenance.

## Known limitations

- No signature verification (0.3), no path validation, CRL or OCSP (0.5), no CMS (0.7), no PKCS#8 or PKCS#12 (0.9).
- A non-ASCII octet in an IA5String name is refused; internationalized names are not converted before 0.5.
- The Certificate Transparency SCT list is kept in its TLS encoding.
- The error-code vocabulary may still change before it freezes in 0.9.

## Install

pkinative 0.1.0 is not on npm. Install the tarball attached to this release — built from the tag, gated, installed as a test and attested by `release-assets.yml`:

```bash
npm install https://github.com/Nizoka/pkinative/releases/download/v0.1.0/pkinative-0.1.0.tgz
gh attestation verify pkinative-0.1.0.tgz --repo Nizoka/pkinative
```

A plain git install (`github:Nizoka/pkinative#v0.1.0`) does not work: `dist/` is not committed.

## Downstream integration notes

- **pdfnative** (0.7 migration target): `parseCertificate` replaces `src/crypto/x509.ts`. The certificate is `Certificate`, with `serialNumber.value` (bigint), `tbsDer` (the signed bytes), `issuer.der` and `subject.der` (for CMS IssuerAndSerialNumber), and extensions through `getExtension` — `subjectKeyIdentifier`, `authorityKeyIdentifier`, `extendedKeyUsage`, `authorityInfoAccess` (OCSP and CA issuers URLs), `crlDistributionPoints` and `ocspNoCheck`. Errors are `PkiError` subclasses with stable codes instead of `Error` strings. pdfnative's SHA-256 bit-length defect (inputs of 512 MiB or more) is fixed in pkinative's hashes and reported to pdfnative as a draft.
- **New public API:** 127 exports, all new; `docs/assets/api.json` lists them.
- **Diagnostics are on by default:** without `onDiagnostic`, each diagnostic code of a call is written once to `console.warn`. pdfnative, which parses certificates of its own signers and of third parties, should pass `onDiagnostic` to route them to its own diagnostics, or `strict: true` where it must refuse any profile violation.
- **Error codes:** every code of `docs/data/errors.json`, all introduced in 0.1.0. An explicitly encoded DEFAULT value is the `PKI_DIAG_DEFAULT_ENCODED` diagnostic, not an error.
- **No PEM shortcut:** compose `decodePem` and `parseCertificate`; there is no `parsePemCertificates`.
